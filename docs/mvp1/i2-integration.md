# I2 · 联调

> **阶段**：I 测试、联调、验收（3-4 天）　**依赖**：H、I1　**工时**：约 1 天

## 目标

前后端联调，修复字段/分页/错误码不一致，验证性能与并发。

## 实施步骤

### 1. 前后端对接
- 对接全部 API，修复字段/分页/错误码不一致。

### 2. 大文件验证
- 大文件（如 50MB PDF）性能与超时验证。

### 3. 并发验证
- 并发上传 10 个文档，验证队列与幂等。

## 验收标准

- [x] 前后端字段/分页/错误码一致。
- [x] 大文件处理不超时不崩溃。（用户指示：跳过自动化全链，手工测；上限拒绝已自动化验证）
- [x] 并发上传队列与幂等正常。

## 验收记录（live，real exit 0）

| # | 场景 | 结果 |
| :- | :--- | :--- |
| 1 | 契约审计 | OpenAPI `ApiResponse_*` 信封 `{code,message,data}` + 实测列表响应分页四字段 `{items,total,page,page_size}` —— 与前端 `api/index.ts` 类型一致 |
| 2 | 并发上传 | **10 文档并发 201 → 10/10 job succeeded，16s**（solo worker 串行队列） |
| 3 | 幂等 | 顺序重复上传同 bytes → `duplicate=true`、同 doc/version，版本数 1 |

**大文件（手工测试项，用户指示跳过自动化）**：

- 自动化已验证边界：50MB+1KB → **413 in 0.8s**（`upload_max_mb=50` 生效，不崩溃）。
- 49MB 上传 → 201（13.3s 落盘）+ 立即 cancel → job cancelled（不烧嵌入），也已实测。
- 全链 50MB 解析+嵌入请手工测（嵌入调用量 ≈ 2.7 万 chunks，不适合 CI/探针）。

**已知限制（如实记录）**：C1 幂等判定为 `(tenant, file_name, hash)` SELECT-then-INSERT 查重——**并发窗口内**两次完全相同的上传可能双双 miss 而各建一 doc；顺序重复上传幂等正确（已验证）。后续可加 DB 唯一约束或行锁收口。
